## Dependências ainda pendentes

Os três alertas de produção representam a cadeia `expo-router → query-string → decode-uri-component`, relacionada ao [GHSA-vcc3-ghjq-m6fr](https://github.com/advisories/GHSA-vcc3-ghjq-m6fr). A versão corrigida de `decode-uri-component` é ESM, enquanto `query-string@7.1.3` depende de uma função CommonJS. Forçar a versão isolada muda esse contrato. A correção automática proposta pelo npm rebaixa o Expo Router para 5.1.11, incompatível com o SDK adotado; não foi aplicada.

A árvore completa inclui ainda ferramentas de desenvolvimento: Firebase CLI, OpenTelemetry/PubSub, Express/body-parser/qs, stream-json e gaxios/uuid. `npm audit fix` sem `--force` e a atualização compatível do Firebase CLI foram executados; os alertas remanescentes não foram ocultados. Não há conclusão de que todas as cadeias sejam exploráveis neste app, nem de que sejam irrelevantes. Repita a auditoria antes de distribuir uma nova versão.

As correções de XML foram resolvidas dentro das linhas compatíveis das dependências, conforme o [GHSA-6gmq-8vp8-gcm6](https://github.com/advisories/GHSA-6gmq-8vp8-gcm6). A atualização SDK 57/RN 0.86.3 preserva a correção da regressão Hermes indicada no [changelog oficial do Expo](https://expo.dev/changelog/sdk-57).

## Limites da interface e próximos passos

Os testes de painel renderizam componentes React com React Native Web; sessão, navegação e componentes nativos auxiliares são simulados. Cobrem bloqueios e renderização condicional, mas não cliques no navegador, efeitos de login, câmera ou permissões do aparelho.

A tentativa de usar Computer Use falhou com `native pipe ... os error 2`. A execução de um Chrome isolado foi rejeitada pela revisão automática com `blocked by policy`. Não se atribui aprovação visual a esta etapa.

1. Autenticar/vincular o EAS pelo roteiro `BUILD_MOBILE.md`, configurar variáveis por ambiente e gerar APK de homologação.
2. Testar com contas distintas em aparelho físico: acesso, câmera/galeria, localização, QR, persistência do SecureStore e revogação de dispositivo.
3. Tratar a próxima extração de domínio com a sequência do [ADR-ARCH-002](adr/ADR-ARCH-002-MONOLITO-MODULAR.md), começando por diretório/pesquisa antes de áreas comerciais críticas.
4. Resolver os alertas remanescentes quando houver atualização compatível e repetir auditoria/testes.

`LAB_ED25519_PQ_BLOCKED`, `pqc_ready=false` e provider pós-quântico indisponível continuam sendo limites explícitos. Esta retomada não declara prontidão para produção.
